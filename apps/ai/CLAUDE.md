# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`@training/ai` — Node 22 ESM agent server. Hono app serving a LangChain agent to the web client through the CopilotKit runtime (AG-UI protocol).

## Commands

```bash
pnpm --filter @training/ai dev         # tsx watch, loads .env and ../web/.env if present
pnpm --filter @training/ai build       # tsup src/index.ts --format esm --target node22 --clean -> dist/index.js
pnpm --filter @training/ai start       # node dist/index.js
pnpm --filter @training/ai typecheck   # tsc --noEmit
```

Build inlines `@training/contracts` via `tsup.config.ts` (`noExternal`). Routes `GET /release-history/latest-version`, `POST /release-history/next-version` and `POST /api/release-email/render` have no web caller. Root shortcut: `pnpm dev:ai`. Tests run with Vitest (`pnpm test`, config in `vitest.config.ts`, `src/**/*.test.ts`). No lint script in this app (root `pnpm lint` only covers apps that define one).


## Architecture

- `src/index.ts` — `CopilotRuntime` with one agent `releaseCopilotAgent` and the `CheckpointAgentRunner` (`runner/`); the base agent is built once and shared by the AG-UI agent and the runner (conversation state is the Postgres checkpointer); Hono mounts `createCopilotEndpoint` at `/api/copilotkit`, plus `GET /health`, which runs `select 1` on the shared pg pool and returns `{ ok, db: { reachable } }` (200, or 503 when the database is unreachable).
- `src/agent/` — `createBaseAgent(pool, options?)` = `createAgent` + `ChatOpenAI`, `tools`; optional `middleware`, `checkpointer`, `systemPrompt` (default `SYSTEM_PROMPT`: static string from `constants/prompts.ts`, ported as-is from the old app; no time block, so the provider prompt cache stays valid; ends with a `RELEASE_FLOW` section: count-only summary, format question, one `renderReleaseNotesPreview` call) via `CreateBaseAgentOptions`. Exports `BaseAgent` type.
- `src/agui/` — `ReleaseNotesAguiAgent` (custom `AbstractAgent`, replaces `@ag-ui/langchain` `LangChainAgent`, whose `chainFn` cannot emit tool results). Runs `agent.stream(..., {streamMode: "messages"})` with the AG-UI `threadId` as `configurable.thread_id`. Text streams token by token. Server tool calls stream as AG-UI `TOOL_CALL_START/ARGS/END` and then `TOOL_CALL_RESULT` when the tool returns; the web gates rendering on completion, so the preview never renders partially. `toLangChainMessages` converts AG-UI history (user/assistant+toolCalls/tool). The draft on screen arrives as an AG-UI `context` entry `{ release, format, text, hash }` (`agui/draft-context.ts`, `findDraftContext`: last entry that parses, `null` = none); `run` passes it in `configurable.draftContext` (an object, so LangGraph does not copy it into checkpoint metadata) and `middlewares/draft-context.ts` appends it as a delimited read-only block to the latest human message in the model request only, so the checkpoint and the system prompt never hold it.
- `src/runner/` — `createCheckpointAgentRunner(agent, pool)` = `CheckpointAgentRunner extends InMemoryAgentRunner` (#122). `connect()` passes through the in-memory replay; if that completes with no event (new process after a restart), it checks `request.ownerId` against `getThreadOwner`, reads `agent.getState` for the thread and emits `RUN_STARTED`, one `MESSAGES_SNAPSHOT` (`toAguiMessages` in `agui/`, tool calls and tool results included, system skipped) and `RUN_FINISHED`. No owner match, no messages or a read error (logged) = empty stream. A pending approval interrupt is not replayed.
- `src/db/` — `createCheckpointer(pool)` (`PostgresSaver` on the shared pool, keyed by the AG-UI `threadId`; `setup()` runs at every start, idempotent; on failure logs and falls back to `MemorySaver`), `createPgPool()` (lazy `pg.Pool` from `DATABASE_URL`, 3 s connection timeout, `error` listener so idle-client errors do not crash the process; reusable by the checkpointer), `createSupabaseAdminClient()` (service-role key, no session persistence), `checkDatabase(pool)` for `/health`.
- `src/middlewares/auth.ts` — `createRequireAuth(supabase)` Hono middleware mounted on `/api/*`: reads `Authorization: Bearer <token>`, verifies with `supabase.auth.getUser`, sets `c.get("userId")` (type `AuthEnv`); missing/invalid token gets 401 `{ error: "Unauthorized" }`, `OPTIONS` passes. `/health` is outside `/api` and stays public.
- `src/routes/slack.ts` — `createSlackRoute()`: `POST /slack/publish` (body `SlackPublishRequestSchema`: `platformId`, `label`, `content` max 35 000), behind `createRequireAuth` mounted on `SLACK_PATH_PATTERN` (`/slack/*`). Posts to `config.slackWebhookUrl` via `utils/post-to-slack-webhook.ts` (`postToSlackWebhook`: JSON `{ text: "*<label>*\n<content>" }`, 10 s `AbortSignal.timeout`, throws `SlackWebhookError`). Returns `{ ok: true }`; errors are `{ error }` with 400 invalid body, 500 missing webhook URL, 502 Slack rejected / network failure, 504 timeout. Messages live in `SLACK_ERROR_MESSAGES` (same wording as web).
- `src/routes/threads.ts` — `createThreadsRoute(pool)`: `GET /api/memory/threads` (covered by the `/api/*` guard) returns `{ threads: ThreadSummary[] }` for `c.get("userId")` from the `threads` table in schema `release-builder-dev` (`THREADS_TABLE`; `db/threads.ts`, the only place that knows its columns), newest `updated_at` first. `resourceId` is the owner id. Rows are created by `ReleaseNotesAguiAgent.run` (empty title, `claimThread`) and titled later by the title step (M-24); the list shows empty-title rows.
- `src/routes/release-history.ts` — `createReleaseHistoryRoutes(pool)`: `GET /release-history` (paged list, cursor), `GET /release-history/latest-version`, `POST /release-history/next-version` (`nextVersion`), `GET /release-history/:id`, `POST /release-history` (save, 201). These sit outside `/api`, so `index.ts` mounts `createRequireAuth` and `userContextMiddleware` on `/release-history` and `/release-history/*`. Queries live in `db/release-history.ts` (scoped to the owner; table `release_history`). The migration `supabase/migrations/20261109000000_create_release_history.sql` creates `public.release_history` (one `release` jsonb per row) and `public.release_sends`. `db/release-history.ts` reads and writes that object (`POST` body `{ release }`, validated with `ReleaseSchema`, saved with status `archived`; search `q` matches `release->>'version'` and `openingLine`). List and detail take `?format=` (default `markdown`) and return `{ id, release, status, format, text, createdAt }`; `text` is rendered on read with `renderRelease` (`utils/release-history-record.ts`), `null` when over the format's limit, never stored. Nothing reads `release_sends` yet.
- `src/routes/release-email.ts` — `createReleaseEmailRoute()`: `POST /api/release-email/render` (`RELEASE_EMAIL_RENDER_PATH`, behind the `/api/*` guard); body is a `ReleaseSchema` release, answers `renderReleaseEmail(release)`, 400 `{ error: "Invalid release" }` on a bad body.
- `src/tools/` — `createRenderReleaseNotesPreview(pool)` (`createTools(pool)` builds the tool array): input `format`, `openingLine`, `changes`, optional `version`/`date`. Code computes the version (`nextVersion` from `getLatestReleaseVersion(pool, userId)`, `userId` from `userContext`) and the date (`formatReleaseDate`), renders only that format with `renderRelease` (`html-email` via `renderReleaseEmail`, plus `subject`), and returns JSON `{ ok: true, release, format, text, hash, subject? }`. `format` is normalized first (trim, lower-case, spaces/underscores to `-`, `RELEASE_FORMAT_ALIASES`: `github`/`gh` = markdown, `html`/`email` = html-email, `appstore`, `googleplay`/`play`). Unknown format = `{ ok: false, error, supportedFormats }`; over-limit = `{ ok: false, error, release, hash }` with no text. `hash` = SHA-256 of the release object (`hashRelease`). `agui/index.ts` maps an `ok: true` result to the `{platform, label, content}` shape the evaluators read.
- Slack publish from chat: `publishReleaseNotesToSlack` is guarded by LangChain `humanInTheLoopMiddleware` (approve/reject) in `createBaseAgent`, which needs the checkpointer wired in `index.ts`. `ReleaseNotesAguiAgent` streams `messages` + `updates`; a `__interrupt__` update ends the run with `RUN_FINISHED { outcome: { type: "interrupt" } }`, and a later run with `input.resume` becomes `new Command({ resume: { decisions } })` (`resolved` + `{decision: "approve"}` approves, anything else rejects). With saved state, a normal turn sends only the user messages after the last assistant message (`trimToNewMessages`). The web answers through `useInterrupt` (`hooks/use-slack-publish-approval.tsx`).
- Model fallback: `middlewares/model-fallback.ts` wraps prebuilt `modelFallbackMiddleware` with a `ChatOpenAI` on `config.fallbackModel` (`AI_FALLBACK_MODEL`, default `DEFAULT_FALLBACK_MODEL`); first in the `createBaseAgent` middleware list. Primary is `config.model` (`AI_MODEL`).
- Prompt-injection guard: `createPromptInjectionGuard(model)` (`utils/prompt-injection-guard.ts`) runs in `ReleaseNotesAguiAgent.run` **before** the graph, for the latest human message (not on resume). A small classifier model (`config.guardModel`, `AI_GUARD_MODEL`, default `DEFAULT_GUARD_MODEL`) returns a structured verdict (`PromptInjectionVerdictSchema`: `safe` | `injection`). `injection` streams `PROMPT_INJECTION_REFUSAL` as a normal AG-UI text message and ends the run; the graph and checkpointer are never touched, so the blocked user message and refusal are not stored. It is not agent middleware on purpose: a `beforeAgent` + `jumpTo: "end"` block was checkpointed (input, step 0 and step 1 all held the message and the refusal). **Fail-closed**: a classifier error replies `PROMPT_INJECTION_CHECK_FAILED`, also unsaved. If a thread has no saved state, `dropGuardedTurns` strips earlier guarded turns from the client history so they are not stored on resend.
- PII redaction (M-28): `middlewares/pii.ts` `createPiiMiddleware()` = prebuilt `piiMiddleware` for `email` (built-in) and `phone` (custom `detectPhone` in `utils/pii.ts`, patterns in `constants/pii.ts`), strategy `redact`, input only. It rewrites the user message in agent state, so the model and the checkpointer both see `[REDACTED_EMAIL]` / `[REDACTED_PHONE]`. URLs and IPs are not redacted (normal in commit text). Registered in `createBaseAgent` after `skillsMiddleware`.
- `src/skills/` — on-demand skills (`commit-pr-parsing`, `classification-rules`, `platform-formatting`, `release-reporting`) as TS modules + `SKILLS` registry. `middlewares/skills.ts` appends a short catalog to the system message each turn and registers the `load_skill` tool; full rules load only when the model calls it. Add a skill = new module + entry in `SKILLS`.

## Cross-app wiring

Web builds the runtime URL from `VITE_API_SERVER_URL` + `RUNTIME_BASE_PATH` (`/api/copilotkit`). Values both apps use (`RUNTIME_BASE_PATH`, `RELEASE_COPILOT_AGENT_ID`, `TIME_ZONE_HEADER`, `TOOL_NAMES`, route paths, change types, release formats and labels, Slack limit, shared schemas) live in `@training/contracts` (`packages/contracts`); `constants/` and `schemas/` here re-export or extend them, so edit the shared package, not a copy. Server default is `http://localhost:4000/api/copilotkit`; keep `AI_PORT` and `VITE_API_SERVER_URL` in step. The web asks for agent id `releaseCopilotAgent` (shared constant). Every web request sends the browser IANA zone in `X-Time-Zone` (`TIME_ZONE_HEADER`, allowed in CORS); `userContextMiddleware` validates it with `resolveTimeZone` (invalid or missing = `DEFAULT_TIME_ZONE`).

## Code style and structure

Follow existing patterns; the folder layout is the convention.

- Path alias `@/*` → `src/*` (tsconfig `paths`). Import across folders with `@/...`, relative only for siblings inside one folder. Imports are ESM, double-quoted strings, semicolons, trailing commas, 2-space indent.
- One concern per folder, each with an `index.ts` barrel (`export * from "./x"`): `constants/`, `schemas/`, `tools/`, `utils/` (pure helpers such as `joinLines`, `formatReleaseDate`). Import from the barrel (`@/constants`), not deep files.
- Adding a tool = 3 pieces, wired together:
  1. name in `constants/tools.ts` → `TOOL_NAMES` (`as const`),
  2. zod schema in `schemas/<tool>.ts` (zod v4),
  3. `tool(...)` in `tools/<tool>.ts` using both, then append to the `tools` array in `tools/index.ts`.
- No magic values inline: model names, prompts, ports, paths go in `constants/`. Env access only in `config.ts`, exported as a single `as const` object.
- Arrow functions + `export const` for everything; `function*` only where a generator requires it (comment says why). Factory functions (`createBaseAgent`, `createAguiAgent`) over module-level singletons.
- Import blocks in `agent/` and `tools/` are grouped under short comment headers (`// Configs`, `// Constants`, `// Tools`, `// Schemas`).
- Comment the *why* (e.g. why tool calls are dropped), as in `agui/index.ts`; doc-comment non-obvious bridges with `/** */`.
- Stay on `createAgent` + prebuilt middleware; no custom LangGraph graphs. LLM does classify/write/interpret; render/validate/save/send stay deterministic code.
- Thread ownership and row lifecycle (#119, #120): `CopilotRuntime` gets `identifyUser: createIdentifyUser(supabaseAdmin)` (`middlewares/auth.ts`, same token check as `createRequireAuth` via `resolveUserFromAuthHeader`; throws when no user resolves), so runtime thread operations are scoped to the caller. `createThreadGate(pool)` (`utils/thread-gate.ts`, optional last argument of `ReleaseNotesAguiAgent`) reads the owner from `userContext`: in `run`, `canUse` (read-only owner check) runs **before** the guard and the state read; a thread of someone else ends with `RUN_ERROR` `THREAD_ACCESS_DENIED_MESSAGE` and no `getState`. After the guard passes, `claim` inserts the owner row with an empty title (`claimThread`, first writer wins, a lost race is refused). After a turn that streamed a reply (an approval interrupt counts, a guard-blocked turn does not) `touch` bumps `updated_at`. `db/threads.ts` helpers: `getThreadOwner`, `claimThread`, `touchThread`, `setThreadTitle`, `hasTitledThread`.
- Thread titles (M-24): after a turn that streamed a reply (and did not end in an interrupt), `ReleaseNotesAguiAgent` calls the optional `ThreadTitleScheduler` after `RUN_FINISHED`. `createThreadTitleScheduler` (`utils/schedule-thread-title.ts`) runs detached and never rejects: if the thread has no titled row (`hasTitledThread`), it asks the model for a title from the first user message and fills it with `setThreadTitle` (updates only an empty title of the same owner, inserts when the row is missing). A guard-blocked turn streams no reply, so it gets no row. The owner id reaches the agent through `userContext` (AsyncLocalStorage `{ userId, timeZone }`, set by `userContextMiddleware` after `createRequireAuth`, which is mounted on `/api/*`, `/release-history*` and `/slack/*`). The `threads` table lives in schema `release-builder-dev` (`DB_SCHEMA`), not `public`, and is created by `ensureThreadsTable` (`db/threads.ts`, awaited at start in `index.ts`, idempotent, logs instead of throwing), not by a migration.
- Answer-quality checks (M-30): after a completed turn (reply streamed, no interrupt; guard-blocked turns are skipped) `ReleaseNotesAguiAgent` calls the optional `AnswerEvaluationScheduler` after `RUN_FINISHED`. `createAnswerEvaluationScheduler(client)` (`utils/schedule-answer-evaluation.ts`) runs the pure checks in `src/evaluators/` (`count-summary-format`, `draft-structure`, `grounded-items`; each `(turn) => { key, score, comment } | null`) detached and posts each score with `client.createFeedback` on the run. Non-blocking rule: never awaited, never rejects; a low score or a throwing evaluator is only logged server-side. No `LANGSMITH_API_KEY` = no client = no-op. The agent run gets a generated `runId` in its config so the feedback has a run to attach to; full tracing tags stay with M-29. Keys and thresholds live in `constants/evaluators.ts`.
- Tracing (M-29): `configureTracing(config.langsmith)` (`utils/configure-tracing.ts`, called once in `index.ts`) sets `LANGSMITH_TRACING` from the key: key set = on (project from `LANGSMITH_PROJECT`), empty = off even if the shell exports `LANGSMITH_TRACING=true`. Each agent run (`agui/index.ts`) is named `release-notes-turn`, tagged `release-copilot`, and carries `thread_id` and `user_id` (from `userContext`) as metadata; model and tool calls nest under it automatically. Names live in `constants/tracing.ts`.
- User memory (F-16): `createUserMemoryStore()` (`db/user-memory.ts`, `PostgresStore` from `@langchain/langgraph-checkpoint-postgres/store` in `DB_SCHEMA`; `setup()` at every start, falls back to `InMemoryStore` with a log) is passed to `createBaseAgent` as `store`. One record per user (namespace `["user-memory", userId]`, key `preferences`) with `tone`, `writingStyle`, `openingLine`. Tools `saveUserPreferences` (merge, new value overwrites), `getUserPreferences`, `clearUserPreferences` (`tools/user-memory.ts`) take the owner from `userContext`, never from model arguments. The prompt rule is its own section `USER_MEMORY_RULE` (`constants/user-memory.ts`), appended last in `SYSTEM_PROMPT`: save only lasting preferences, one-line confirmation. F-17: `createUserTemplateMiddleware(store)` (`middlewares/user-template.ts`, registered right after `skillsMiddleware` when a store is given) reads the record on every model call and appends `buildUserTemplateBlock` (`utils/user-template.ts`, pure, unit-tested) to the end of the system message, so a change applies to the next generation in any thread and the static prompt stays identical for prompt caching. No user, empty record or store error = request unchanged (error logged).
- Phase 2 config: `config.resendApiKey` (`RESEND_API_KEY`, optional, empty = unset) and `config.emailFrom` (`EMAIL_FROM`, default `DEFAULT_EMAIL_FROM`); scheduler settings (`SCHEDULER_*`) and `STORE_LIMITS` live in `constants/`. Deps `resend` and `@js-temporal/polyfill` are installed, not used yet.
